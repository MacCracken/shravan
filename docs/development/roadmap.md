# Development Roadmap

**Current: v2.9.2.** Shipped history lives in `CHANGELOG.md`; this file is forward-looking only.

## Where we are

| Codec | Decode | Encode | Checked against |
|-------|--------|--------|-----------------|
| WAV | PCM 8/16/24/32, float 32/64 | same | ffmpeg (float 64, both ways) |
| AIFF | PCM | PCM | ffprobe (rates to 384 kHz) |
| FLAC | all subframe types, MD5 verify | Fixed only | `flac`: 18 depth × channel × level files bit-exact, and `flac -t` passes shravan's output |
| ALAC | full, in MP4 and QuickTime | none | ffmpeg: bit-exact, mono to 7 channels, 16/24-bit |
| MP3 | MPEG-1/2/2.5 Layer I/II/III | none | ffmpeg: Layer III exact at all 9 rates. Layers I/II: minimp3 |
| AAC-LC | all 13 rates, TNS, short blocks, M/S, intensity, PNS | long blocks, M/S, intensity, PNS | ffmpeg both ways. Decode is exact apart from PNS noise |
| Opus | all 32 TOC configs | CELT mono and stereo | libopus: 64 of 64 vectors within ±2 LSB |
| MP4 | AAC and ALAC, first audio track | none | ffmpeg, including QuickTime v1/v2 |

Real encoder output with reference decodes is part of the suite (`src/interop_fixtures.cyr`,
regenerated by `scripts/gen-interop-fixtures.py`). Every fix in 2.9.2 was proven by reverting it and
watching those tests fail.

The remaining distance to **3.0.0** is (1) hardening what exists, (2) the encoders the suite still
lacks, (3) the rest of the Opus encoder.

## v2.9.3 — P(-1) sweep: audit, hardening, optimization, refactor, security · **NEXT**

No new features. Run the full P(-1) process from `CLAUDE.md`, then repair everything it finds. 2.9.2
found four codecs broken behind a green suite, so assume more of the same until a reference says
otherwise. The items below are what is already known.

### Audit: cross every path that has not met a reference
- Promote the 2.9.2 comparison rig to `scripts/interop.sh` and a CI job: sweep rate × depth × channels
  against ffmpeg, flac and lame, per frame, in both directions. It only ever lived in a scratchpad.
- Rebuild the libopus vector comparison and fold it into that job. `scratchpad/opusref`,
  `silkref` and `silkoracle` were scratchpad-only and are gone, so this is a rebuild, not a move.
- Paths no external file has reached yet:
  - AIFF and AIFF-C real files, WAV EXTENSIBLE real files
  - Ogg Opus end to end from `ffmpeg -c:a libopus`
  - MP3 Layers I/II against ffmpeg rather than minimp3
  - FLAC at 32-bit, with wasted bits, variable block size, and more than 2 channels
  - ALAC from Apple's own encoder (only ffmpeg's has been tested), and 8 channels
  - AAC with more than 2 channels (SCE + CPE + LFE), PCE, and `pulse_data`
- Search for the rest of the bug class 2.9.2 hit: `/ 2` and `0 - ((0 - x) >> n)` where a floor is
  required, and any hand-written table offset.

### Repair: known defects, decisions needed
- **One-shot decoders stop at about 6.3 minutes of stereo.** The 2^25-sample cap (SEC-023/027/029, 256
  MB of f64) makes a 7-minute 44.1 kHz FLAC return `ERR_DECODE` through `codec_open`. Decide between
  raising the cap, chunked output, or steering long files to the streaming API, then apply one answer
  everywhere.
- **PCM encoders are not the inverse of the decoders.** WAV, AIFF and FLAC encoding multiply by
  2^(N-1) - 1 and truncate; decoders divide by 2^(N-1). A decode then re-encode moves nearly every
  sample by one LSB, so a "lossless" transcode is not. The fix changes the output of three encoders and
  how +1.0 clips, so it needs a decision.
- `src/stream.cyr` has no IEEE float handling: check what float WAV does through the streaming decoder.
- `fuzz_decode`'s AAC seeds run rarely because AAC is slow; raise them once the optimizations below land.

### Optimization
- **AAC dequantisation calls `f64_pow` per nonzero coefficient.** 0.6 s of 22 kHz stereo takes 2.5 s to
  decode, 4× slower than real time. A precomputed x^(4/3) table should remove nearly all of it.
- `perf: FFT-based MDCT/IMDCT preserving the verified TDAC convention` (O(N²) today). AAC decodes 1 s
  of stereo in about 0.9 s even on simple tones.
- `perf: PCM SSE2/unrolled hot loops`.
- Benchmarks are too coarse: `pcm_u8_to_f64_4096` moves 25% on code layout alone (33–66 µs for the same
  loop), so judge it with care or redesign it.

### Hardening
- Per-frame allocation in the AAC decoder (`alloc` in the synthesis path) against a bump allocator that
  never frees. Reuse scratch as `_alac_state_new` does, then measure RSS on a long file.
- Run the fuzzers under the 6.7 toolchain's checks: `cyrius fuzz --poison`, and the bounds-checked mode.

### Refactor
- The three-harness split exists for a ~3.15 MB code buffer that has been a growable 64 MiB region since
  Cyrius 6.4.49. Decide whether to merge the harnesses, then correct `CLAUDE.md`, `test-all.sh` and CI.
- Run `cyrius fmt` over the nine non-canonical `src/*.cyr` files as a dedicated, no-logic-change commit.
- `src/bench.cyr` carries inline copies of library code that can drift from it.
- sankoch is compiled into every binary with no call site in `src/`. Measure the cost and decide. (Its
  `detect_format` is what the 2.9.2 wrapper works around.)
- Stale documentation: the README performance table and the `sankoch` row in `CLAUDE.md`.

### Security
- `test/fuzz: Opus decode target` (≥90K calls, 0 crashes), with real libopus packets as seeds. AAC and
  MP4 already run in `fuzz_decode`, and 2.9.2 added real-encoder seeds for them.
- Re-audit the SEC-numbered bounds for the code 2.9.2 rewrote: ALAC, MP4 esds parsing, ID3v2 frames.

## v2.10.x — the rest of the suite, matured

### v2.10.0 — FLAC encoder
`feat(flac)`: real LPC encoder (autocorrelation + Levinson-Durbin + quantized coefficients), partitioned
Rice, adaptive stereo, CONSTANT subframes, SEEKTABLE writing. Fixed prediction only today.

### v2.10.1 — AAC encoder
`feat(aac)`: re-enable TNS (prediction-gain gated, within `TNS_MAX_BANDS`), short windows, ATH floor and
tonality-adjusted SMR, optional rate/distortion scale-factor loop. Check quality per rate: the psy model
and the M/S, PNS and intensity thresholds assume 44.1 kHz band positions.

### v2.10.2 — MP4 and gapless
`feat(mp4)`: multi-track selection, edit lists (`elst` priming and end trim, so AAC comes out at the
reference's length), and the same for MP3 via the LAME header.

## v2.11.x — SILK encode: the analysis front end · large

This makes the encoder actually encode: the writers and quantisers shipped in 2.8.0, but shravan cannot
encode SILK audio until this exists. Verify each function numerically against libopus on the same input.
- `feat(silk): silk_burg_modified_FLP + silk_find_LPC_FLP` (LPC analysis; the only heavy float function
  on the unvoiced path).
- `feat(silk): silk_noise_shape_analysis_FLP + silk_process_gains_FLP`.
- `feat(silk): silk_NSQ`, the noise-shaping quantiser that produces the excitation. Fixed point
  throughout, 32-bit wrapping; the riskiest single step.
- `feat(silk): silk_encode_frame_FLP orchestration + the gainMult rate loop`, then the gate: a shravan
  SILK frame that libopus decodes to audio **correlating with the input**, not merely a legal frame,
  which an all-zero excitation would satisfy while proving nothing.
- Note: the float→fixed boundaries use `lrintf` (round half to **even**), which f64 code must reproduce
  deliberately.

## v2.12.x — the voiced path and hybrid encode · large

- `feat(silk): pitch analysis (silk_pitch_analysis_core_FLP), silk_find_LTP_FLP, silk_quant_LTP_gains,
  LTP scaling`. The bitstream writer already handles voiced frames.
- `feat(opus): hybrid encode (SILK low band + CELT high band over one range coder) + the encoder
  mode/bandwidth decision and TOC assembly`, so shravan encodes **every** Opus config libopus decodes.

## v3.0.0 — production-quality, interoperable, hardened suite · MAJOR

The major bump: every codec value-verified end to end in both directions, fully interoperable, safe on
hostile input, no known correctness bugs.

**Gate:**
- Opus encodes *and* decodes every config, interop-verified with libopus both ways.
- FLAC LPC encoder real.
- All decoders fuzzed to 0 crashes, Opus included.
- Reference comparison running in CI, not a scratchpad.
- Benchmarks tracked in the CSV history.
- Zero known correctness bugs.

**Backlog:** items that need the major bump or wait on the gate.
- Remove the `detect_format` wrapper. `shravan_detect_format` replaced it in 2.9.2 and no consumer calls
  it, but it is public API, and removing it is what clears the last duplicate-function warning.
- Any change to the PCM scaling convention that 2.9.3 decides needs a compatibility break.

## Post-3.0

- `feat: DSD64/128/256 + DoP (1-bit sigma-delta path)`: new format, additive.
- `feat(aac): HE-AAC (SBR, PS)`. MP4 reports these as unsupported since 2.9.2 rather than playing the
  core at half rate.

## Working discipline (unchanged)

Every change lands as a small verified bite: build clean, all assertions pass, new tests + benchmarks for
new code, decode stays bit-exact through any shared-code refactor. A round-trip through shravan's own
encoder proves nothing: judge decoders by maximum sample error against a reference, per frame, on real
encoder output, and encoders by what that reference does with their output. Never claim a stage done
until it is value-verified against something other than shravan.
