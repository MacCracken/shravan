# Development Roadmap

**Current: v2.12.0.** Shipped history lives in `CHANGELOG.md`; this file is forward-looking only.

Streaming decoders (WAV, AIFF, FLAC, and `decode_reader` over them) match the one-shot decoders sample
for sample however the input is split, hold only one unfinished chunk or frame, and have no length
ceiling. One-shot decodes stop at `shravan_set_max_samples` (2^26 interleaved samples by default) with
`ERR_TOO_LARGE`.

Real encoder output with reference decodes is part of the suite (`src/interop_fixtures.cyr`,
regenerated by `scripts/gen-interop-fixtures.py`), and `scripts/interop.sh` sweeps rate × depth ×
channels against ffmpeg, flac, mpg123 and libopus in CI. Every fix since 2.9.2 was proven by reverting
it and watching a test fail.

### Paths no reference has reached

Open until a reference file or decoder exists for each.
- **MPEG-2.5 8 kHz mixed blocks.** ffmpeg and minimp3 disagree on the band layout and no conformance
  vector covers it, so shravan's layout is unchanged and unverified.
- **AAC `pulse_data`** is refused (`ERR_UNSUPPORTED_FMT`): no available encoder writes it.
- **ALAC from Apple's encoder** and **FLAC with a variable block size**: no tool here produces them.
  ffmpeg's ALAC and `flac`'s fixed-size output are verified.
- **ID3v2 grouped frames** are read per the spec; neither ffmpeg nor mutagen reads them at all.
- **AAC coupling channel elements** are refused (`ERR_UNSUPPORTED_FMT`): no available encoder writes them.
- **AAC 22.2 and channel configurations 11, 13 and 14**: ffmpeg's encoder writes none of them. Their
  element placement and channel order are checked against ffmpeg's source (`ff_aac_get_che`,
  `sniff_channel_order`), not against a file.

The remaining distance to **3.0.0** is the rest of the Opus encoder. The FLAC encoder is real since
2.10.0, the AAC encoder since 2.10.1, multichannel AAC and Opus decode since 2.10.3, and the SILK encoder
since 2.11.3 (voiced frames since 2.12.0).

## v2.12.x — hybrid encode and the Opus encoder layer · large

The SILK encoder codes voiced and unvoiced frames since 2.12.0 (`silk_encoder_new`, `silk_encode`,
`silk_encode_opus`), byte for byte libopus's `silk_Encode` wherever libopus's float stages round as
shravan's doubles do, and on real speech as well as libopus's own encoder. Verify the way 2.11 and
2.12.0 did: `scripts/gen-silk-vectors.py` records libopus's stages, and `src/silk_tests.cyr` holds
shravan's packets to libopus's.
- `feat(opus): hybrid encode (SILK low band + CELT high band over one range coder) + the encoder
  mode/bandwidth decision and TOC assembly`, so shravan encodes **every** Opus config libopus decodes.
  That is libopus's `opus_encode` around SILK, which `silk_encode_opus` does not do yet:
  - input at the API rate, resampled to the internal one;
  - the input high-pass (`dc_reject`, 3 Hz, or VOIP's variable cutoff, which reads the smoother
    `silk_hp_variable_cutoff` keeps since 2.12.0);
  - stereo SILK (mid/side prediction, mid-only frames);
  - in-band FEC (LBRR frames; the LTP scaling's FEC term waits on it) and DTX.
- SILK complexity 2 and up: `silk_NSQ_del_dec`, the delayed-decision quantiser libopus selects there.
  `silk_encoder_new` refuses those complexities until it exists. (The pitch estimator's complexity 2,
  which complexity 8 and up selects, is already in and checked.)
- Note: the float→fixed boundaries use `lrintf` (round half to **even**), which f64 code must reproduce
  deliberately.

## v3.0.0 — production-quality, interoperable, hardened suite · MAJOR

The major bump: every codec value-verified end to end in both directions, fully interoperable, safe on
hostile input, no known correctness bugs.

**Gate:**
- Opus encodes *and* decodes every config, interop-verified with libopus both ways.
- FLAC LPC encoder real. (Since 2.10.0: levels 0–8, within 0.1% of `flac`'s sizes.)
- All decoders fuzzed to 0 crashes, Opus included. (Since 2.9.3: `./fuzz/run.sh 90000`, cold starts
  and poison mode included.)
- Reference comparison running in CI, not a scratchpad. (Since 2.9.3: the `interop` CI job.)
- Benchmarks tracked in the CSV history.
- Zero known correctness bugs.

**Backlog:** items that need the major bump or wait on the gate.
- Remove the `detect_format` wrapper. `shravan_detect_format` replaced it in 2.9.2 and no consumer calls
  it, but it is public API, and removing it is what clears the last duplicate-function warning.
  `scripts/check-collisions.sh` allows it by name until then.

## Post-3.0

- `feat: DSD64/128/256 + DoP (1-bit sigma-delta path)`: new format, additive.
- `feat(aac): HE-AAC (SBR, PS)`. MP4 reports these as unsupported since 2.9.2 rather than playing the
  core at half rate.

## Working discipline (unchanged)

Every change lands as a small verified bite: build clean, all assertions pass, new tests + benchmarks for
new code, decode stays bit-exact through any shared-code refactor. A round-trip through shravan's own
encoder proves nothing: judge decoders by maximum sample error against a reference, per frame, on real
encoder output, and encoders by what that reference does with their output. Never claim a stage done
until it is value-verified against something other than shravan.
